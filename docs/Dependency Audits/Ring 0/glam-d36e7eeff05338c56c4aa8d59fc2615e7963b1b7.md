# glam Ring 0 Audit: d36e7eeff05338c56c4aa8d59fc2615e7963b1b7

## Decision

**Retain as the current Ring 0 math implementation and public math vocabulary.**

This decision is limited to `glam` 0.29.3 at the exact source revision below
and the `std` feature. It does not approve a version range, additional features,
or an upstream update without the ADR-0010 update procedure.

The retain decision recognizes an existing public commitment: Tokimu exposes
`Mat4`, `Quat`, `Vec2`, `Vec3`, and `Vec4` through `tokimu_core::math`, and the
rendering and 3D corpus use those types directly. Replacing that vocabulary
would be a distinct compatibility and performance migration, not an incidental
dependency cleanup.

## Role And Alternatives

- Native Ring responsibility served: provider-neutral foundational math values
  and transforms.
- Direct callers and public API exposure: `tokimu_core::math` re-exports
  `Mat4`, `Quat`, `Vec2`, `Vec3`, and `Vec4`; the `tokimu` facade re-exports
  `tokimu-core`; `tokimu-render::Camera` exposes `Mat4`; and the current 3D
  corpus consumers import `Mat4` and `Vec3` (with `Vec4` where material or
  clipping data requires it) through `tokimu_core::math`.
- Alternatives considered:
  - **Wrap:** removes foreign names from public API but still retains the full
    implementation and creates conversion/compatibility cost for existing
    render and corpus callers.
  - **Replace:** a Tokimu-owned math implementation would need to reproduce a
    broad matrix, quaternion, transform, and SIMD-sensitive behavior surface.
    No concrete evidence currently shows that to be lower-risk than the pinned
    implementation.
  - **Move:** cannot move the current shared mathematical representation out of
    the Native Ring without changing the accepted core/render boundary.
  - **Remove:** not viable while the current real callers require the types.
- Reason it remains Ring 0: foundational math representation is shared engine
  vocabulary, rather than a backend- or application-specific mechanism.

## Source And Build Review

- Complete selected closure: `glam` has no runtime, build-script, or
  procedural-macro dependencies under Tokimu's selected `std` feature.
- Source size: 170 Rust source files; the cached 0.29.3 package contains 232
  files and approximately 4.6 MiB including documentation, tests, and benches.
- Build scripts and procedural macros: no `build.rs`; none selected.
- Generated or prebuilt artifacts: no prebuilt artifact is selected. Generated
  swizzle source is present in the upstream tree and is covered by the pinned
  revision.
- Unsafe/FFI/assembly: 78 Rust source files contain `unsafe`. The selected
  implementation uses architecture intrinsics and representation casts for
  SIMD/vector operations. It exposes no foreign-library dependency or external
  process, filesystem, network, or environment access in the selected closure.
- Allocation, threading, synchronization, global state, I/O, panic, and error:
  the selected math crate has no external dependency closure or build script;
  it is a value-math implementation. Callers remain responsible for normal
  floating-point exceptional values and for validating any externally supplied
  transform data at Tokimu boundaries.
- Determinism and targets: the same pinned Rust source is selected for native
  and WASM. Target-specific SIMD lowering remains an implementation concern;
  native and WASM build validation is required on every revision update.
- Toolchain finding: current Rust compilation emits upstream
  `unused_attributes` warnings from generated swizzle trait-method code. The
  pinned revision compiles today, but the compiler describes the pattern as
  becoming a future hard error. This is an explicit update/reopening trigger.

## ADR-0008 And ADR-0009 Evidence

- Performance: retention avoids an unmeasured rewrite of a currently used math
  surface. A replacement or wrapper proposal must carry comparative benchmark,
  binary-size, and compile-time evidence before changing this decision.
- Validation: focused tests and locked offline native/WASM builds passed after
  local-source migration. The Ring 0 source audit derives the closure from the
  declared `tokimu-assets`, `tokimu-core`, `tokimu-input`, and
  `tokimu-runtime` roots. The resulting foreign source is only the approved
  local `glam` submodule, with no registry or remote Git source.
- Failure behavior: `glam` receives no untrusted bytes, filesystem paths,
  network messages, or provider callbacks through this dependency boundary.
  Input validation remains at the resource, scene, and presentation boundaries
  that construct math values.

## Public Vocabulary Confirmation

The retained foreign vocabulary is deliberate and currently bounded to the
five re-exports in `crates/tokimu-core/src/math.rs`: `Mat4`, `Quat`, `Vec2`,
`Vec3`, and `Vec4`. Repository consumers confirm this is not an unused
convenience re-export:

- `tokimu-render::Camera` stores and accepts `Mat4`, and uses `Vec3` to build
  its current perspective view;
- `crates/tokimu` re-exports the core facade, making the same math vocabulary
  available to facade consumers; and
- 3D, CAD, GLB, shader, hole-punch, FPS, stereo, and audio-visualizer corpus
  entries import the core math values directly.

No additional `glam` type, trait, or module is re-exported from a Tokimu crate
by the current source scan. Adding one is a reopening trigger; replacing the
five retained names requires a measured compatibility migration rather than a
local implementation substitution.

## Update, Removal, And Reopening

- Owner and update procedure: Tokimu maintainers update the parent gitlink to
  one reviewed upstream commit, compare source and selected features, rerun the
  Ring 0 audit and Native validation, and update this record or create a new
  revision record.
- Removal strategy: first introduce a provider-neutral Tokimu math vocabulary
  or compatibility wrapper with real callers; only then migrate public callers
  and remove the re-export. Do not replace types opportunistically.
- Reopening triggers:
  - any `glam` source, feature, gitlink, or Cargo-path change;
  - a relevant advisory, license change, unsafe/FFI change, or source mismatch;
  - a native/WASM behavior or performance regression;
  - the current upstream warning becoming a compiler error; or
  - a proposal to expose additional `glam` types or traits through Tokimu.
